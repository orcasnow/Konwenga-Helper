# Konwenga Helper

[Football LAB](https://www.football-lab.jp/) の試合レポートページ 1 本の URL から、試合記事の下書きに使う表とグラフを一式生成し、Google ドキュメントにまとめて出力する Google Colab 用ノートブックです。

J リーグの試合レビューを書くたびに、スタッツ表の転記・チャートの作り直し・画像の貼り付けを手作業でやっていた部分を丸ごと自動化することを目的にしています。

- **バージョン**: Ver.9.0.0
- **実行環境**: Google Colab 専用（Google 認証・Drive・Docs API を使うため）
- **入力**: Football LAB の試合レポート URL（例: `https://www.football-lab.jp/nago/report?year=2026&month=09&date=06`）
- **出力**: Google ドキュメント 1 本（`report_YYYYMMDD`）

---

## 生成されるもの

1 回の実行で、以下が 1 つの Google ドキュメントに順番に並びます。

| 成果物 | 内容 |
| --- | --- |
| チャンスビルディングポイント（CBP）表 | 試合レポートの CBP サマリ表 |
| CBP 詳細表 | 攻撃 / パス / クロス / ドリブル / シュート / 奪取 / 守備 / セーブ の 8 セクション |
| スタッツ表 | 試合レポートのスタッツ表 |
| レーダーチャート（今節） | 今節の両チーム CBP を、同カテゴリのリーグ平均を基準にした相対値で比較 |
| レーダーチャート（次節） | 自チームと次節対戦相手の CBP 比較 |
| CBP データ表 | 上記レーダーチャートの数値表 |
| タイムライン | 時間帯別のボール保持率に、シュートとゴールを重ねた積み上げグラフ |
| シュートチャート | 両チームのシュート位置図（ピッチ背景画像に合成した PNG 2 枚） |

実行の最後には**実行結果サマリ**が必ず出力され、成果物ごとの OK / NG / SKIP と警告の一覧を確認できます。「完了と出たのに記事を書き始めてから表が欠けていた」という事故を防ぐための仕組みです。

## 使い方

### 1. ノートブックを Colab で開く

`Konwenga_Helper.ipynb` を [Google Colab](https://colab.research.google.com/) で開きます。GitHub から直接開く場合は、Colab の「GitHub」タブにこのリポジトリの URL を貼り付けてください。

### 2. セルを順番に実行する

ノートブックは 8 セル構成です。上から順に実行してください。

| セル | 役割 |
| --- | --- |
| 1/8 | 環境セットアップ（apt / pip / Playwright のインストール） |
| 2/8 | 共通基盤（import・ログ設定・実行結果サマリ） |
| 3/8 | **設定**（通常触るのはここだけ） |
| 4/8 | クラブマスタ（チームカラー・別名テーブル） |
| 5/8 | スクレイピング |
| 6/8 | チャート生成（タイムライン・レーダー） |
| 7/8 | Google Docs / Drive 出力 |
| 8/8 | オーケストレーションと実行 |

セル 1/8 はランタイム起動後に 1 回だけ実行すれば十分です。2 回目以降の実行（試合を変えて回すとき）は、設定セルを書き換えて 3/8 以降を流し直してください。

### 3. Google アカウントの認証

セル 8/8 の実行中に Colab の認証ダイアログが出ます。Google ドキュメントと Google ドライブへのアクセスを許可してください。生成されたドキュメントの URL は、実行結果サマリの `Docs URL` 行に表示されます。

## 設定項目

セル 3/8 の Colab フォームから指定します。

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `TARGET_MATCH_URL` | — | 解析対象の Football LAB 試合レポート URL |
| `MY_TEAM` | `名古屋グランパス` | 自チーム名（表のセル色や次節レーダーに使用） |
| `NEXT_TEAM` | `V・ファーレン長崎` | 次節の対戦相手。空にすると次節レーダーはスキップ |
| `MY_TEAM_COLOR` | `#d80c18` | 自チームの表示色（`#RRGGBB`） |
| `OPPONENT_TEAM_COLOR` | `#005ce6` | 相手チームの表示色（`#RRGGBB`） |
| `CBP_RANKING_CATEGORY` | `auto` | CBP ランキングの取得カテゴリ。`auto` / `j1` / `j2` / `j3` |
| `CBP_RANKING_YEAR` | `100` | CBP ランキングの年度パラメータ |
| `DRIVE_TEMP_FOLDER_NAME` | `Konwenga Helper 一時画像` | Drive 上の一時画像フォルダ名 |
| `REVOKE_PUBLIC_LINKS_AFTER_EXPORT` | `True` | Docs 貼り付け後に画像の公開リンクを解除する |
| `DRIVE_TEMP_RETENTION_DAYS` | `7` | この日数を過ぎた一時画像をゴミ箱へ移す |
| `LOG_LEVEL` | `INFO` | `INFO` / `DEBUG` / `WARNING` |

色の指定が `#RRGGBB` 形式でない場合は警告を出したうえで既定色にフォールバックします。

### CBP ランキングのカテゴリについて

レーダーチャートは、各クラブの CBP を**同じカテゴリのリーグ平均で割った相対値**として描きます。`auto` はランキング表に自チームが載っているカテゴリを実測で判定するため、J1 / J2 / J3 のどのクラブでもそのまま使えます。カテゴリを固定したい場合だけ `j1` / `j2` / `j3` を明示してください。

## 画像の扱いとプライバシー

Google ドキュメントに画像を挿入するには、いったん Drive 上に公開リンク付きで置く必要があります。本ツールでは次の順で扱います。

1. 一時画像を専用フォルダ（既定: `Konwenga Helper 一時画像`）にアップロードし、`anyone / reader` 権限を付与する
2. Docs への貼り付けが終わったら、その公開権限を削除する
3. 保持期間を過ぎた一時画像をゴミ箱へ移す（完全削除はしない）

画像は `insertInlineImage` の時点で Docs 側にコピーされるため、公開権限を外しても本文の表示は維持されます。`REVOKE_PUBLIC_LINKS_AFTER_EXPORT` を `False` にすると公開されたままになります（URL を知っていれば誰でも閲覧可能）。この場合は実行結果サマリに SKIP として記録されます。

## 昇降格でメンテナンスする場所

触るのはセル 4/8 の 2 つのテーブルだけです。

- `RAW_CLUB_COLORS` — クラブ略号ごとのホーム / アウェイカラー
- `RAW_TEAM_ALIASES` — クラブ名・略称から略号への対応

未登録のクラブがあっても実行は止まりません。試合ページのチームセレクタから別名を自動学習し、略号を採番したうえで警告として実行結果サマリに残します。警告が出たらテーブルへの追記を検討してください（自動採番されたクラブは既定色で描画されます）。

## 実行が失敗したときは

実行結果サマリの NG / 警告を起点に確認してください。

| 症状 | 確認すること |
| --- | --- |
| 試合レポート取得が NG（HTTP 404） | URL の年月日を確認。試合がない日付は 404 になります |
| 試合レポート解析が NG（表が 0 個） | Football LAB のページ構造が変わった可能性。セル 3/8 の `ScraperSelectors` を確認 |
| 表の列数に関する警告 | 想定列数（CBP サマリ 7 列 / スタッツ 7 列）と実際が食い違っています。崩れた表がそのまま Docs に載っていないか確認 |
| チーム略称が HOME / AWAY のまま | 比較表（`div.tblCompare`）を取得できていません |
| シュートチャートが 2 枚未満 | 静的 HTML から取れない場合は Playwright にフォールバックします。それでも失敗する場合はタイムアウト（既定 60 秒）を疑ってください |
| Google 認証が NG | Colab の認証ダイアログで Docs / Drive の権限を許可したか確認 |
| 別名テーブル未登録の警告 | セル 4/8 の `RAW_CLUB_COLORS` / `RAW_TEAM_ALIASES` に追記 |

より詳しい経過を見たい場合は `LOG_LEVEL` を `DEBUG` にして再実行してください。

## 設計上の方針

- **DOM 依存を 1 か所に集約** — Football LAB の CSS セレクタはすべて `ScraperSelectors` にまとめてあります。相手サイトの構造が変わったときに見る場所をここだけにするためです。
- **黙って素通ししない** — 表の構成が想定外だったり、クラブの別名が解決できなかったりした場合は、処理を続けつつ必ず警告として記録します。
- **取得は 1 回だけ** — CBP ランキング 7 ページは今節・次節で共有し、試合 HTML はタイムライン・シュートチャートで再利用します。相手サイトへのアクセス回数を抑えるためです。
